# 方法库管理

```text
methods/
└─ 仪器类型_具体型号[_测试模式]/
   ├─ METHOD.md
   ├─ scripts/                       有实际需要才建立
   ├─ versions/                      更新时保留旧版本
   └─ submethods/
      └─ 用户命名的子方法/
         ├─ METHOD.md
         ├─ scripts/                 按需
         └─ versions/                按需
```

目录不预置未经确认的方法。方法名是可直接定位的身份；通用方法目录严格按第三层命名，子方法目录必须由用户命名。禁止悄悄转为另一个缩写或别名；名称不适合作为文件夹时请用户选择合法名称。

## 选择

先逐字符精确找到仪器目录，再核对METHOD中的类型、型号和模式、确认状态及适用结构。省略模式必须是登记的有效身份，不是未知模式的回退。

TXT明确指定子方法时，在该通用方法内定位并核对适用性。聊天明确指令可以指定，但与TXT冲突时提问。无指定时可以按测试数据类型与子方法名字推荐候选，任何相似度都不授权执行；用户明确选定后才能用。已有方法“完全相同可直跑”的条件包含方法选择已明确。通用方法若仅提供读取规则，不足以自动决定科学计算。

## 建立与更新

本次方案与永久保存是两次独立确认。本次可使用任务范围内临时候选方案，经用户批准后执行；未经长期保存确认，不在正式methods中创建新方法或改变已确认方法。

完成新/变化方案后展示差异和适用条件，询问四选一：
1. 创建通用方法：按仪器类型_型号_模式命名；如果该目录已存在，不创建冲突副本，说明更新或子方法选项。
2. 更新已有方法：指定目标和变更范围，保留旧版METHOD及必要脚本快照，记录新版本与确认信息。
3. 新建子方法：请用户命名，明确继承的通用方法版本、适用条件及变化步骤。
4. 不更改：仅保留本次结果和执行说明，不写入方法库。

普通数据量、时间点或声明为可变的参数变化不等于方法变化。输入格式、运算、选取规则、统计定义或布局变化则需要明确评估。

每个方法说明必须包括：身份/状态/版本/确认记录、适用类型和模式、输入识别与结构、描述必需参数、样品和重复映射、按顺序的Excel公式和单元格布局、默认单sheet与允许的显式拆分、Results定义、组内选取处理、预览方式、已验证案例及限制。确认记录不得编造用户话语或日期。

用户日后可说“修改某通用方法的某子方法”。精确定位后展示差异方案，按用户已明确的修改授权实施；歧义则统一问。不修改其他子方法。更新通用方法必须分析其子方法依赖，不能静默把变化传播到所有子方法。子方法记录所基于的通用版本；不兼容时暂停而非默认升级。
